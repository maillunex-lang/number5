# Lunex AFK - Roadmap

Статус: **живая карта**. Обновлено 2026-11-20 после выгрузки UI Prototype v0.1 + Admin Studio в `main`.

Последовательность проектирования по-прежнему: **D** (документы) → **C** (контент) → **A** (детальное ТЗ на фундамент) → онлайн-реализация. Локальный UI/Studio-прототип **не заменяет** CORE-01 и серверный цикл MVP.

## Фактический прогресс (репозиторий)

| Артефакт | Состояние | Где |
|---|---|---|
| Документы D (GDD / MVP / STRUCTURE / ARCHITECTURE / CONTENT-01) | Утверждены / зафиксированы | `docs/` |
| UI Prototype v0.1 (Godot 4.7.2, локальный клиент) | **Сделано** на `main` | `project.godot`, `scenes/`, smoke |
| Версионные контент-пакеты (клиент только читает) | **Сделано** (пакет `0.1.0`) | `content/packages/` |
| Lunex Admin Studio (локальный файловый API) | **Сделано** (не Go/Postgres admin API) | `admin-studio/` |
| Android debug APK | **Собрано** ранее (не в git) | `docs/ANDROID_BUILD.md` |
| CONTENT-02+ (фракции, 10–15 героев, 30 этапов, экономика) | **Не утверждено** | ожидает решений |
| CORE-01 (Go API + PostgreSQL + CI сервера) | **Не начато** | нужен этап A / доступы |
| Авторитетный серверный бой / прогресс / платежи | **Не начато** | после AUTH/BATTLE |

## Ближайший рабочий порядок

1. **CONTENT-C** — утвердить фракции, ростер героев, 30 этапов, врагов, черновик экономики (решения пользователя).
2. Параллельно без блокер-решений: укреплять пакетный пайплайн, CI валидации, документацию схем, демо-контент-заготовки в JSON **без** выдачи за утверждённый лор.
3. **TZ-A** — детальное ТЗ API/БД/боя после CONTENT-C.
4. **CORE-01** — Go + PostgreSQL + Docker (нужны доступы/VPS или явное «можно локальный Docker»).
5. Подключить клиент к реальному API; заменить `DemoData` прогрессом с сервера.

## Тестовые ворота

1. Smoke: запуск, вход, навигация. *(локальный smoke — PASS)*
2. Functional: бой, награды, прогресс, призыв. *(только демо)*
3. Graphics: атласы, VFX, размеры экранов.
4. Performance: FPS, RAM, загрузка, батарея на Android от 6 ГБ.
5. Network: обрывы, повторные запросы, восстановление.
6. Server: транзакции, параллельные бои, нагрузка.
7. Release: подпись, обновление, откат, iPhone Web/PWA.
8. Content packages: `tools/validate_content_package.sh` + целостность sha256. *(локально — PASS)*

## Управление изменениями

Новые решения фиксируются отдельным кодом/доком и обновляют GDD, архитектуру, MVP и эту дорожную карту согласованно. Целевой набор гильдий, межсерверных функций и полной монетизации **не** обязателен для v0.1 Alpha, если не включён в `MVP.md`.
