# H6 — приёмка на устройстве

Критерий ROADMAP: playback ↔ серверная timeline, reconnect через `GET /battle/{id}`, повтор claim с тем же `idempotency_key`.

Автоматика (CI / `go test`): timeline shape, детерминизм seed, GET reconnect, claim replay, сдвиг этапа. Ниже — то, что проверяет только телефон.

## Перед тестом

1. Установить **свежий APK** с VPS (`latest.apk` после merge H6 + FIX-GODOT-DEPLOY + ATOMIC).
2. Online-вход (гость или аккаунт), CDN/API доступны.
3. Записать: модель, Android OS, versionName / versionCode APK.

## Чеклист (5–10 мин)

| # | Шаг | Ожидание | ✓ |
|---|---|---|---|
| 1 | Карта → CH01-01 (или текущий) → бой | COMBAT-02 стартует без DEMO-заглушки | |
| 2 | Смотреть playback | Юниты получают урон/смерть в порядке timeline; в конце victory/defeat как на сервере | |
| 3 | Во время боя свернуть приложение / выключить сеть на 3–5 с, вернуть | Бой **продолжается** или восстанавливает timeline (не «ломается» в пустой экран) | |
| 4 | Досмотреть до результата → «Забрать» | Награды ONLINE, кошелёк обновился | |
| 5 | Снова нажать получение / повторить claim (если UI даёт) | Нет двойной выдачи; тот же receipt (`replayed`) | |
| 5b | Пройти уже очищенный этап ещё раз → Забрать | **Без наград** (тренировка); баланс не растёт; first clear только один раз | |
| 6 | Карта после победы | Открыт следующий этап | |
| 7 | Новый бой → Home во время playback → вернуться в бой при наличии battle_id | Клиент тянет `GET /battle/{id}` и доигрывает | |

## Не баг

- DEMO timeline без `battle_id` (офлайн) — только fallback.
- Поражение: claim 422, наград нет — ожидаемо.

## После прогона

Владелец пишет в чат: **H6 device OK** (или список FAIL с шагом #).  
Агент закрывает пункт в STATUS/ROADMAP.
