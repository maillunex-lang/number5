# AI_WORKFLOW — процесс работы ИИ-исполнителей

Связано с корневым [`AGENTS.md`](../AGENTS.md). Обновлять этот файл только при смене процесса.

## Цикл

```
Получение задачи
  → Изучение STATUS + AI_HANDOFF + ROADMAP (+ точечно код)
  → Проверка: не сделано ли уже? есть ли блокер?
  → План (короткий) в ответе пользователю при крупных изменениях
  → Ветка cursor/<topic>-9d0b
  → Реализация
  → Тесты (QUALITY_GATES)
  → Обновление STATUS / ROADMAP / AI_HANDOFF / TECH_DEBT
  → Commit + push + PR (без auto-merge)
  → Отчёт по шаблону AGENTS §14
  → Передача следующему исполнителю
```

## Параллельная работа

- Разные ИИ = **разные ветки** и непересекающиеся области (например docs vs server vs Godot UI).  
- Один модуль (`mux.go`, `0.9.0` package) — не править параллельно без согласования.  
- Worktree допустим; не `push --force` в чужую ветку.

## Определение готовности

Функция **не** DONE, если есть только JSON, кнопка, класс или маршрут. Нужны:

1. Реализация по слою (data / UI / server / PG).  
2. Интеграция (кто вызывает).  
3. Проверка из QUALITY_GATES или явный NOT_VERIFIED в отчёте.  
4. Обновлённый статус в STATUS/ROADMAP.

Шкала: DONE · PARTIAL · DEMO · DATA_ONLY · DOC_ONLY · BLOCKED · NOT_STARTED.

## Когда остановиться и спросить пользователя

- Смена баланса / сюжета / публичного API.  
- Удаление файлов или пакетов.  
- Деплой / VPS / чужие БД.  
- Неясный конфликт канона и кода после чтения AGENTS §4.

## Обновление AI_HANDOFF

После **каждого** завершённого PR или крупного коммита исполнитель обновляет `docs/AI_HANDOFF.md`:

- last commit SHA  
- что DONE/PARTIAL  
- блокеры  
- next 3 задачи  
- что читать первому  

Файл **не** автогенерируется — ручное обновление обязательно.
