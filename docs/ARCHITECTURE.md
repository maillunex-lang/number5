# Lunex AFK - Architecture
Статус: целевая архитектура + факт на `main` (аудит 2026-11-20).  
**Есть:** Godot UI, Admin Studio, контент-пакеты OTA (dev HTTP), CORE-01 Go API (memory + код Postgres adapter).  
**Нет / блокер:** изолированный production Lunex (отдельная БД, CDN HTTPS), бинарный арт. Живой VPS существует, но не считается готовым Lunex-продом. Детали: `docs/STATUS.md`, `docs/ROADMAP.md`.

## Общая схема
Godot 4.7.2 (Android APK / Web-PWA) -> HTTPS API -> Go modular monolith -> PostgreSQL.
Отдельная React + TypeScript Lunex Admin Studio взаимодействует с защищённым административным API. Раздача игровых пакетов через HTTPS/Caddy и версионный манифест. Docker Compose для стартового развёртывания.

## Клиент
- Портретная ориентация 9:16, адаптация под экраны.
- Собственный Lunex UI Kit на базе глубоко адаптированного godot-ui-template (UI-CORE-001 C); импорт после проверки лицензии и совместимости Godot 4.7.2.
- Гибрид сцен (SCENE-ARCH-001 C): четыре корневые вкладки в общем Shell, полноэкранный бой и крупные системы отдельными сценами; единый Router и общие модальные слои.
- Расширенное сохранение UI-состояния (NAV-STATE-001 C): прокрутка хаба, выбранный герой, фильтры, открытые панели, режимы и черновики отрядов. Серверные данные не подменяются локальными.
- Предзагрузка всех основных экранов при запуске (SCENE-LOAD-001 A); тяжёлые пакеты контента по требованию и кешируются по версии. Следить за RAM/временем запуска.
- Четыре навигационные вкладки: Карта / Герои / Главная / Битва. Призыв открывается из Алтаря в главном хабе, отдельной вкладки нет.
- Многослойные 2.5D-фоны, анимированные 2D-спрайты, эффекты и настройки качества. Главный хаб прокручивается вертикально с параллаксом, содержит 8+ интерактивных зданий и развивается с прогрессом.
- Android: нативный рендер Godot. iOS: Web/PWA через совместимый браузерный рендер Godot, без Vulkan.
- Клиент не является источником истины для прогресса, инвентаря, валют, боёв и наград.

## Серверные модули
auth, profiles, heroes, inventory, formation, battle, campaign, afk, summons, economy, payments, pve, arena, guilds, social, events, content, assets, admin, audit.
В MVP реализуются только необходимые модули; интерфейсы будущих модулей проектируются без преждевременного разбиения на микросервисы.

## Авторитетность и защита
- Сервер проверяет полномочия, состояние игрока, стоимость операций, лимиты, выдачу наград.
- Бой полностью рассчитывается сервером; результат и последовательность событий передаются клиенту для воспроизведения.
- Начисления и списания выполняются атомарно; повторные запросы защищены идемпотентностью.
- Призыв использует серверный генератор, опубликованные вероятности и сохраняемую историю гарантий.
- Платёжные подтверждения проверяются сервером; права доступа к админке разграничены, изменения аудируются.
- Резервные копии БД и проверка восстановления обязательны до внешней альфы.

## База данных
PostgreSQL 16: пользователи, учётные данные/сессии, герои, отряды, инвентарь, прогресс, балансы и журнал операций, бои, баннеры/гарантии, AFK, события, PvP, гильдии, версии контента. Конкретная схема и миграции проектируются на этапе A.

## Ресурсы
GLB/готовые спрайты -> Blender sprite baking -> атласы и метаданные -> проверка -> версия пакета -> публикация -> загрузка/кеш на клиенте.
Версионный манифест, контроль целостности, совместимость пакетов, поэтапная публикация и откат. Клиент скачивает обязательный минимум и подгружает остальное по необходимости.

## Админка
Lunex Admin Studio: игроки, герои, этапы, экономика, баннеры, события, версии, визуальная студия (PNG/WebP/GLB, превью, промпты, назначение ассетов), мониторинг и аудит. Операции публикации и массовые изменения требуют подтверждения.

## Развёртывание и сборки
Ubuntu 24.04, Go, PostgreSQL 16, Docker Compose, Caddy, React/TypeScript. CI/CD с development, testing, production; подписанный тестовый APK как можно раньше. Целевой минимум Android: 6 ГБ RAM; FPS, память, размер APK и Web/PWA-совместимость подтверждаются реальными тестами.

## Открытые технические решения
Схема API, авторизация/refresh, конкретные таблицы, протокол доставки результатов боя, лимиты запросов, хранилище ассетов, политика хранения кеша, наблюдаемость, схема резервирования, Android-подпись и совместимость Web-экспорта. Не считать эти детали уже утверждёнными.
