# LUNEX AFK: Башкортостан: Разлом эпох
# AFK-QUEST-EXPEDITION-01 · AFK-награды, ежедневные задания, экспедиции, недельный цикл

**Назначение:** самостоятельное подробное ТЗ для Cursor по игровому циклу между боями. **Статус:** проектные решения, не реализовано. **Репозиторий:** `maillunex-lang/number5`, Godot 4.7.2, целевая архитектура Go + PostgreSQL, Admin Studio. **Дата:** 2026-11-20.

## 0. Источники и непреложные связи
1. `LUNEX_AFK_BASHKORTOSTAN_RAZLOM_EPOH_6_CHAPTERS_CURSOR.md`: шесть глав, 180 основных этапов `CH01-01`…`CH06-30`, сюжет и карта. Не создавать параллельную кампанию.
2. `LUNEX_AFK_RAZLOM_EPOH_FACTIONS_45_HEROES_CURSOR.md`: H01–H45, F01–F06, 14 N / 11 R / 10 SR / 7 SSR / 3 UR. Только эти ID, не придумывать новых героев.
3. `LUNEX_AFK_RAZLOM_EPOH_HERO_PROGRESSION_EQUIPMENT_LOOT_CURSOR.md`: ресурсы, 6 слотов, 12 сетов, Tier I–VI, AFK экипировка **на 1 Tier ниже максимальной пройденной главы**, AFK кап 12 часов, никакого relic и уникальных артефактов; 20 полноценных повторных наград кампании в день, затем 25% золота/опыта без предметов. AFK **не расходует** этот лимит.
4. `LUNEX_AFK_RAZLOM_EPOH_GACHA_45_HEROES_CURSOR.md`: ×10 выдаёт десять героев за 8 свитков/2400 алмазов, pity отдельный. AFK и экспедиции **не призывают** героев сами, только выдают свитки, фрагменты и ресурсы. Один дубликат = 30 фрагментов конкретного Hxx.
5. `LUNEX_AFK_RAZLOM_EPOH_MONETIZATION_VIP_SUBSCRIPTIONS_CURSOR.md`: магазин VIRTUAL_FREE, 3 подписки, VIP 0–11, сезонный пропуск 28 дней / 30 уровней, `daily_login`, `daily_campaign`, `daily_afk`, `daily_upgrade`, `weekly_campaign`, `weekly_boss`, `weekly_summon`, `season_story` и их **существующие** pass_xp. Не начислять pass_xp дважды.
6. Все дневные сбросы **06:00 Europe/Moscow**, расчёт сервером в UTC. Не зависеть от часового пояса/часов телефона. Ресурсы `gold`, `hero_xp`, `essence`, `diamonds`, `summon_scroll`, `faction_scroll`, `afk_hour` и материалы экипировки использовать с теми же ID.

## 1. Основной игровой цикл
`Сюжетный бой → открыть новый AFK-уровень → уйти из игры → накопление сервером → забрать ресурсы → отправить героев в экспедиции → выполнить ежедневные задания → улучшить отряд → следующий бой`.

Три системы независимы: **AFK** генерирует награды за прошедшее время; **ежедневные/недельные задания** фиксируют реальные игровые действия; **экспедиции** занимают героев на таймере и дают отдельные награды. Никакая из них не создаёт скрытые боевые результаты и не расходует гарантии гачи.

## 2. AFK: базовая механика
- Накопление начинается после `CH01-03` (предложение для MVP), даже если клиент закрыт; до открытия показывать карточку с условием.
- Сервер хранит `last_claim_at`, `afk_progress_stage`, `accumulated_seconds`, `pending_reward_snapshot`, `config_version`. Награда считается из времени и **максимально пройденного этапа**. Нельзя выбрать непройденный этап.
- Максимум **12 часов** накопления. После достижения капа таймер останавливается, интерфейс пишет «Хранилище заполнено».
- Награды копятся в секундах, выдача по завершённым минутам. Остаток секунд переносится после claim, без потерь и без дублирования. Минимальный claim 60 секунд.
- При первом открытии AFK нет наград «за прошлые дни». При сбросе сезона AFK таймер не обнулять.
- Уровень дохода обновляется при первом прохождении более позднего этапа: накопленное время **до** повышения оплачивается по старой ставке, время **после** по новой. Хранить сегменты или начислять в серверный аккумулятор на границе прогресса; не пересчитывать всю ночь по последнему этапу.
- При сбое сети сервер возвращает один и тот же receipt по idempotency key. После перезапуска Godot остаток времени и баланс совпадают с сервером.
- AFK не даёт алмазы напрямую, не даёт UR/SSR героев, не выдаёт `relic`, уникальные артефакты и сюжетные награды за первое прохождение.

### 2.1. Ставки ресурсов по главам (стартовый баланс)
| Глава максимального прогресса | Gold/час | Hero XP/час | Essence/час | Ore/час | Доступный Tier AFK предмета |
|---|---:|---:|---:|---:|---|
| 1 Уфа | 1800 | 700 | 30 | 3 | I, только после CH01-20 |
| 2 Шиханы | 3200 | 1300 | 50 | 5 | I |
| 3 Белорецк | 5200 | 2100 | 80 | 8 | II |
| 4 Стерлитамак 2050 | 8000 | 3400 | 125 | 12 | III |
| 5 Иремель | 12000 | 5200 | 190 | 17 | IV |
| 6 Хозяева времени | 17500 | 7800 | 280 | 24 | V |

**Исключение главы 1:** Tier I как минимальный, начиная с CH01-20; до него AFK выдаёт только ресурсы и материалы. В главах 2–6 строго `max(1, cleared_chapter-1)`. Все значения проектные и должны быть вынесены в конфиг.

### 2.2. Точная формула
`earned(resource) = floor(sum_over_segments(rate_per_hour(stage_segment) * seconds / 3600) + fractional_remainder)`; дробный остаток сохраняется в фиксированной точке (например, micro-units), чтобы частые сборы не давали меньше ресурсов. `ore` = материал того Tier, который доступен на момент сегмента. Для прогресса внутри главы можно использовать коэффициент `1 + 0.01*floor((stage_index-1)/5)` (макс +5%); если сложность баланса нежелательна, MVP оставить только главы. Выбор должен быть единственным и зафиксированным в конфиге; **по умолчанию только глава**.

### 2.3. Предметы в AFK
После открытия `CH01-20` сервер каждые **4 полных часа AFK** делает один независимый roll: 25% предмет, иначе ничего. При успешном ролле: 65% common, 30% uncommon, 5% rare; только Tier по таблице, из совместимого общего пула без гарантий конкретного сета. Роллы считаются по **накопленному времени** (4/8/12 ч), даже если пользователь собирает каждые 10 минут: хранить `equipment_roll_progress_seconds`, не сбрасывать при сборе. Максимум 3 попытки за любые 12 накопленных часов. Никаких epic/legendary/relic, уникальных артефактов, pity кампании. Награды при переполнении инвентаря попадают в `pending_loot` согласно RPG-LOOT.

### 2.4. Купоны AFK (`afk_hour`)
1 купон = награда **за 1 час** по текущей ставке на момент активации, но без предметных роллов, без сюжетного прогресса и без начисления опыта пропуска. Серверный лимит 4 купона/игровой день для обычного игрока (включая купоны из подписки и магазина); не менять 12-часовой лимит естественного накопления. Купон расходуется атомарно с начислением. Если в кошельке 0 купонов, кнопка неактивна. Не допускается передача купонов между аккаунтами.

## 3. Ежедневные задания и награды
### 3.1. Правила
- Открываются после `CH01-05`. Задания обновляются каждый день в 06:00 МСК. Выполненное, но не забранное задание: **автоматически отправить награду в почту** при сбросе с 7-дневным сроком, чтобы игрок не терял заработанное. Невыполненные задания сгорают. Каждая награда имеет уникальный ключ `(account,task,period)`.
- События фиксируются сервером: `battle_won`, `afk_claimed`, `hero_upgraded`, `summon_completed`, `expedition_completed`, `boss_won`, `daily_login`, `equipment_upgraded`. Клиент не может прислать произвольное число выполненных боёв.
- Повторная победа учитывается для задания, даже если исчерпаны 20 полноценных наград повторных боёв, но не считается «новым сюжетным этапом».
- `daily_login`, `daily_campaign`, `daily_afk`, `daily_upgrade` **уже существуют в пропуске**: здесь используются те же события и отдельная награда за задачу, но pass_xp за них начисляется только по правилам сезонного пропуска, без второго начисления из этой таблицы.
- Для новых игроков не ставить невыполнимые задания: призыв доступен после открытия алтаря, экспедиции после `CH01-10`; до этого заменить их на доступные альтернативы с сопоставимой наградой.

### 3.3. Ежедневная шкала активности
За каждую уникальную выполненную задачу +10 очков активности, максимум 120. Сундуки на 20/50/80/100 очках, каждый 1 раз за день:
- 20: `gold 3000`, `hero_xp 1000`.
- 50: `essence 150`, `diamonds 30`.
- 80: `summon_scroll 1`, `ore 8`.
- 100: `diamonds 70`, `summon_scroll 1`.

**Проходимость:** 10 из 12 задач позволяют взять 100 очков; задания с недоступной системой заменяются альтернативами и не уменьшают достижимый максимум. За день можно получить 2 обычных свитка + 100 алмазов через сундуки, плюс небольшие ресурсы; это **не** 10 бесплатных призывов ежедневно. Сундуки не открываются автоматически без claim, но при сбросе заработанные незабранные отправляются в почту.

| `wq_boss_3` | 3 победы над боссами | hero_xp 8000 + ore 20 | `weekly_boss`: +100 pass_xp |

## 5. Сезонный пропуск и события: без двойного начисления
- Источником `pass_xp` остаётся MONETIZATION: `daily_login 20`, `daily_campaign 30`, `daily_afk 20`, `daily_upgrade 20`, `weekly_campaign 120`, `weekly_boss 100`, `weekly_summon 80`, `season_story 250`.
- Один и тот же подтверждённый бой может двигать прогресс и дневного, и недельного, и сезонного задания, но **каждая награда каждого задания выдаётся ровно один раз**.
- Достижимость 3000 XP за 28 дней: 90 XP/день × 28 = 2520, 300 XP/неделю × 4 = 1200, плюс сезонная задача 250; теоретически 3970. Это позволяет завершить сезон без покупок, даже с пропусками. В коде не суммировать XP из двух интерфейсов за одно задание.
- В `VIRTUAL_FREE` премиум-линия активируется бесплатно, но не меняет AFK-скорость и шансы дропа.

## 6. Экспедиции: устройство
### 6.1. Разблокировка и слоты
- Открываются после `CH01-10`, объясняются коротким туториалом «Разведчики Разлома».
- **Базовые слоты:** 2 параллельные экспедиции на аккаунт. `sub_moon` добавляет **+1 слот**, пока подписка активна, в соответствии с MONETIZATION. Не придумывать бонус слота для других подписок или VIP. Максимум 3 в этой версии.
- В экспедицию отправляется 1–3 уникальных героя H01–H45. Один герой может быть только в одной активной экспедиции. В **MVP** герой, находящийся в экспедиции, **может участвовать в сюжетном 5v5 и PvP**, чтобы idle-механика не блокировала игру. Это явно показывать в интерфейсе. Нельзя отправлять неоткрытого героя.
- Нет риска смерти/потери героя или предмета. Экипировка не снимается. Экспедиция не требует клиентской симуляции боя и не создаёт новые анимации: карточка локации + портреты + шкала времени.
- У каждой экспедиции `expedition_id`, `mission_template_id`, `start_at`, `finish_at`, `hero_ids`, `success_chance_snapshot`, `reward_snapshot`, `status`. После завершения claim отдельной транзакцией. Пока награда не получена, слот занят (MVP); при истечении подписки уже запущенная третья экспедиция завершается нормально, но новый запуск сверх двух слотов запрещён.

### 6.2. Условия успеха и состав
У каждого задания 1 рекомендуемая фракция (F01–F06), 1 класс и минимальная суммарная сила. Успех не должен зависеть от RNG до абсурда: `chance = clamp(65% + 10% * count_matching_faction + 10% * has_matching_class + 5% * power_meets_requirement, 65%, 95%)`; максимум 3 героя, `count_matching_faction` от 0 до 2 для расчёта (максимум +20%). Неудача выдаёт 50% золота/XP, но **не** редкий ресурс. На экране показывать точную вероятность до запуска. Случайный результат фиксируется сервером в момент завершения; retry claim не меняет его.

### 6.6. Дневная доска миссий
Каждый день в 06:00 МСК генерировать 6 доступных карточек: по 2 short, 2 medium, 2 long из открытых направлений. **Не генерировать недоступные главы**. Игрок может обновить доску один раз бесплатно, затем обновление за `gold 2000`, максимум 2 платных обновления/день; никаких алмазов. Запущенная миссия сохраняет snapshot и не меняется после обновления доски. Если игрок исчерпал лимит завершений типа, соответствующие карточки становятся неактивными до сброса. Незапущенные миссии исчезают при следующем сбросе, уже запущенные продолжаются.

### 6.7. Экспедиции и фрагменты героев
Чтобы не ломать гачу, **персональные фрагменты** выдаются не случайным UR, а через долгую репутационную цепочку: за 10 успешных `long` экспедиций одной фракции выдаётся `faction_insignia:Fxx` ×1; 5 знаков можно обменять на 10 фрагментов **выбранного уже открытого героя** той же фракции (N/R/SR/SSR; UR пока исключить). Лимит обмена 1 раз в 30 дней/аккаунт. Если в выбранной фракции нет открытых героев подходящей редкости, обмен неактивен, знаки сохраняются. Это не дубликат: дубликат гачи по-прежнему = 30 фрагментов. Отдельный экран обмена с подтверждением, не автоматическая выдача. Все значения конфигурируемые.

## 7. Визуальный интерфейс Godot 9:16
1. **Главная / AFK-хранилище:** сундук, прогресс `07:23 / 12:00`, 4 ресурсных иконки, кнопка «Собрать», превью ожидаемого количества, статус «Заполнено». Без нового рига персонажа; 1 общий VFX свечения.
2. **Ежедневные задачи:** вертикальные карточки с иконкой, прогрессом `2/3`, наградой, кнопкой «Забрать»; сверху шкала активности 20/50/80/100; таймер до 06:00 МСК.
3. **Недельные задачи:** те же компоненты, другой фильтр; счётчик до конца недели.
4. **Экспедиции:** 2–3 слота вверху, ниже 6 карточек миссий с временем, шансом успеха, наградами, рекомендованной фракцией, портретами; выбор 1–3 героев; подтверждение и таймер; результат успех/неудача.
5. **Сезонный пропуск:** не дублировать экран из MONETIZATION; задача отображает прогресс в обоих местах через общую серверную модель.
6. **Уведомления:** AFK заполнен, экспедиция завершена, ежедневный сундук доступен. Не спамить; максимум 1 уведомление на событие и пользовательские настройки. Push не обязателен для MVP.
7. **Маршруты:** сохранить четыре вкладки `Карта / Герои / Главная / Битва`; AFK и экспедиции входят через хаб, задания через иконку «Задания». Не добавлять пятую вкладку.
8. **Оптимизация:** переиспользовать фоны шести глав, 6 иконок ресурсов, 3 иконки длительности, 1 сундук и 1 универсальный анимированный эффект. Не создавать 18 отдельных анимаций экспедиций. Low Quality и reduced motion.

## 8. Системные правила и защита экономики
- Любая награда идёт через общий `wallet_ledger` из MONETIZATION и `equipment_ledger` из RPG-LOOT, со стабильным `source_ref` и уникальным ключом.
- AFK считается только на сервере, но при временной недоступности серверной архитектуры разрешён изолированный офлайн sandbox, явно помеченный `DEMO`, не синхронизируемый с онлайном.
- Время берётся из сервера; отрицательная разница времени = 0; `max_elapsed=12h`; запрос с поддельным client timestamp игнорируется.
- Награды за задачи и экспедиции не привязаны к подписке; третий слот по `sub_moon` - единственное влияние подписки на экспедиции в MVP.
- Уровень VIP не повышает AFK-скорость и шанс особого ресурса, пока это отдельно не утверждено.
- Отдельно вести `reward_source`: `afk_natural`, `afk_coupon`, `daily_quest`, `weekly_quest`, `expedition`, `season_pass`. Это важно для метрик и борьбы с повторной выдачей.
- Капы повторных боёв, естественного AFK и экспедиций независимы. AFK купон не двигает естественный таймер и не считается `wq_afk_24h`.
- Игроку показывать шанс, длительность и награду до запуска экспедиции. Не скрывать вероятность неудачи.

## 9. Данные, API и PostgreSQL
### 9.1. Конфиги
Версионированные файлы `afk_rewards.json`, `daily_quests.json`, `weekly_quests.json`, `expeditions.json` в совместимом расширении контент-пакета. Проверить текущий `manifest.json`/`active.json` и валидатор перед добавлением. Клиент получает публичное описание, но серверные лимиты и награды берёт из авторитетного snapshot конфига.

```json
{
  "schema_version": 1,
  "timezone": "Europe/Moscow",
  "daily_reset_hour": 6,
  "afk": {"max_seconds": 43200, "min_claim_seconds": 60,
    "rates_per_hour": {"chapter_1": {"gold": 1800, "hero_xp": 700, "essence": 30, "ore": 3}},
    "equipment_roll_interval_seconds": 14400,
    "equipment_roll_chance_bp": 2500,
    "coupon_daily_limit": 4},
  "expeditions": {"base_slots": 2, "subscription_extra_slot_id": "sub_moon",
    "missions": [{"id": "EXP-01-01", "chapter": 1, "duration_seconds": 7200,
      "recommended_faction": "F01", "recommended_class": "ranged",
      "min_team_power": 1300, "special_reward_chance_bp": 800}]}
}
```

`recommended_class` должен совпадать с **реальными enum класса в проекте**: в примере `ranged` условен; при импорте сверить с HEROES и текущим Godot/Go. `ore` обязан содержать Tier в серверном grant, а не один неразличимый ресурс.
