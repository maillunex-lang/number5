**Важно:** доля в каталоге **не равна вероятности выпадения**. Вероятности, гарантия, цены и дубликаты должны утверждаться отдельно и отображаться игроку до призыва. N-герои намеренно многочисленны, но **не бесполезны**: доступны как материал развития/экспедиций/ранней игры. Никаких скрытых списаний: разбор только с подтверждением, заблокированные/избранные не разбираются. Не использовать N как обязательную жертву, если герой в активном отряде.

### Базовые правила роста (проектные)

- Статистика ниже указана на **уровне 1**, без снаряжения, звёзд, талантов и фракционных бонусов. HP/ATK/DEF/SPD/ENERGY; SPD влияет на интервал автоатаки, ENERGY на стартовую энергию (из 1000).
- На уровень `L` до 100: `HP(L)=round(HP1*(1+0.075*(L-1)))`, `ATK(L)=round(ATK1*(1+0.060*(L-1)))`, `DEF(L)=round(DEF1*(1+0.055*(L-1)))`. Скорость не растёт от уровня. Это **предварительные формулы**; не включать в прод без тестов.
- Базовый интервал автоатаки: `2.0 * 100 / SPD` секунд, ограничение [0.8, 3.5] с; энергия за автоатаку +100, за полученный удар +35, ульта стоит 1000, начальная энергия указана в карточке. Бой 90 секунд, автоматическая активация ульты.
- Сила лечения и щита считается от ATK кастера, если прямо не указан максимальный HP. Суммарное снижение входящего урона от брони и резистов не должно превышать 70%; шанс контроля на боссах снижен на 60%.
- Базовая критическая вероятность 5%, критический множитель 150%, точность 100%, уклонение 0%; индивидуальные навыки меняют эти значения. Контроль одного типа повторно в течение 5 с имеет убывающую эффективность.
- Никакого гарантированного превосходства UR: команда SR/SSR при грамотной синергии должна проходить основную кампанию.

## 4. Полные игровые карточки всех 45 героев

**Стандартизация:** у каждого героя есть автоатака, два активных навыка (автокаст), пассивный навык и ульта (автокаст). Приоритет AI: спасение союзника с HP<35% → доступная ульта → контроль опасного врага → активный навык → автоатака. Длительности, коэффициенты и кулдауны в секундах. Цели: танки/воины передний ближайший, стрелки/маги ближайший доступный, убийцы задний с минимальным HP, поддержка/лекари союзник с минимальной долей HP, если навык лечит.

## 6. Прогрессия и баланс (проектные параметры)

### Статы и рост

- Уровни: N до 40, R до 60, SR до 80, SSR/UR до 100 **до повышения ранга**. Не вводить жёсткий кап, если он противоречит текущей системе прогрессии; проверить текущий GDD.
- Звёзды 1–5: +5% HP/ATK/DEF за звезду сверх первой, не усиливают SPD. Дубликаты дают фрагменты, фрагменты не должны исчезать при переполнении инвентаря.
- Экипировка: оружие (ATK), броня (DEF/HP), артефакт (уникальный эффект); ранги N/R/SR/SSR/UR могут иметь разные потолки, но численные значения утверждаются после тестов.
- Уровень навыка 1–5: активный коэффициент +5% от базового значения за уровень, длительность контроля **не растёт**; ульта +4% за уровень.
- Контроль: провокация, оглушение, замедление, метка; босс иммунен к принудительному перемещению, а длительность оглушения сокращена.
- Лекари не атакуют собственных союзников, поддержка не даёт энергию выше 1000, щиты имеют лимит 30% максимального HP цели.
- Разные источники одного баффа используют strongest-wins; одинаковые DoT не складываются бесконечно; временные эффекты обновляют длительность с ограничением.

### Целевые тесты баланса

1. 1000 серверных симуляций на каждую контрольную пару составов, фиксированные seed и версионирование формул.
2. Стартовый N/R-отряд должен выигрывать CH01-01 при базовом развитии; CH01-30 достижим без UR.
3. 5 UR не должны автоматически побеждать сбалансированную команду SSR/SR на сопоставимой силе.
4. Отдельно проверять UR-возрождение Ориэль и перенаправление урона Зорвена на бесконечные циклы.
5. У каждой фракции должен быть минимум один жизнеспособный состав с танком/лечением или компенсирующей механикой; при дефиците разрешён смешанный отряд.
6. Все 45 героев должны пройти валидацию диапазонов: HP>0, ATK>0, DEF>=0, SPD 40–180, кулдауны >=1, уникальные ID, валидные target rules.

## 7. Визуальное производство (Godot 4, 9:16, 2.5D)

- **Стиль:** Clean Stylized Anime Fantasy; читаемые силуэты на экране шириной 360–430 dp, без микродеталей и чрезмерной вспышки.
- **Редкости:** N = простая рама, R = бронзовая, SR = серебряная, SSR = золотая с мягкой анимацией, UR = анимированная уникальная рама. Редкость не обозначать только цветом, добавить текст и пиктограмму.
- **Внешний вид:** каждую карточку выше использовать как текстовый бриф для художника/ИИ. Не смешивать оружие/костюм разных героев.
- **Атласы:** PNG/WebP с альфой, стандартные клипы idle/attack/skill_1/skill_2/ultimate/hit/death/victory, события hit frame, hitbox, VFX sockets; проверить размеры атласов на Android.
- **Анимации:** 8–12 fps для второстепенных N, 12–18 fps для SR+, ульта до 24 fps при достаточном бюджете; финальные FPS по профилированию, не обязательно для каждого кадра.
- **Экономия:** N могут разделять скелет/базовый цикл, но иметь уникальные портреты, силуэты, оружие, цвета, VFX и текст. Не обещать 45 полностью уникальных rigged GLB в MVP.
- **Ресурсы:** APK только обязательные assets, остальные докачивать через безопасный HTTPS манифест, с SHA-256, кешем и откатом после реализации updater.

## 8. Контракт данных для Cursor

Предлагаемый отдельный файл `content/packages/{version}/hero_roster.json`, если клиентская схема допускает; иначе расширить текущий `heroes.json` без ломания существующего формата. Не внедрять две конкурирующие базы героев.

```json
{
  "schema_version": 1,
  "factions": [{"id":"F01","name_key":"faction.F01.name","kind":"core","bonus_thresholds":[2,3,5]}],
  "heroes": [{
    "id":"H01", "name_key":"hero.H01.name", "faction_id":"F01",
    "rarity":"SSR", "role":"tank", "era":"ancient",
    "base_stats":{"hp":2600,"atk":150,"def":138,"spd":65,"energy":0},
    "abilities":[
      {"slot":"basic","id":"H01_BASIC","target":"nearest_enemy","coefficient_pct":100},
      {"slot":"active_1","id":"H01_A1","cooldown_s":12},
      {"slot":"active_2","id":"H01_A2","cooldown_s":16},
      {"slot":"passive","id":"H01_P"},
      {"slot":"ultimate","id":"H01_U","energy_cost":1000}
    ],
    "asset_id":"heroes/h01", "story_npc_id":"NPC_H01"
  }]
}
```

**Образец выше демонстрирует поля, но не является сериализацией карточек:** числа в реальном JSON должны браться из таблиц H01–H45, а не из примерного `base_stats` выше. Нужны машиночитаемые `effects[]`, `targeting`, `duration_s`, `chance_pct`, `stack_rule`, `boss_multiplier`, `cooldown_s`, `scaling_stat` для **каждого** навыка. Не хранить только свободный текст, если бой должен его исполнять.

### Схема эффекта (рекомендуемая)

```json
{
  "effect_type":"damage|heal|shield|buff|debuff|taunt|stun|energy|revive",
  "target":"front_enemy|lowest_hp_enemy|lowest_hp_ally|all_allies|all_enemies",
  "value_pct":140, "scaling_stat":"ATK", "duration_s":0,
  "chance_pct":100, "cooldown_s":8, "stack_rule":"refresh",
  "boss_duration_multiplier":0.4, "tags":["magic","rift"]
}
```

Сериализовать **все 45** героев в валидные записи, все умения в детерминированные эффекты; обеспечить миграцию ранее существующих H01–H15 без изменения их ID. Текущие `heroes.json` и `DemoData` сначала исследовать. Не пытаться трактовать строку описания навыка как код.
