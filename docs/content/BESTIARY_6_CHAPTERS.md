## 3. Общие правила боя и числовой баланс
- Все значения **проектные** и требуют проверки в симуляции. Бой 5v5, полностью автоматический, сервер авторитетен; клиент только воспроизводит. Противник не становится призываемым героем.
- Формулы характеристик на этапе `s` (1..180) при коэффициенте роли: `HP = round((190 + 32*s) * role_hp * tier_hp)`, `ATK = round((26 + 4*s) * role_atk * tier_atk)`, `DEF = round((12 + 1.4*s) * role_def * tier_def)`; `SPD` фиксирован по ригу. Эти формулы заменить на таблицу прогрессии при балансировке; не смешивать с реальным серверным прогрессом игрока.
- Множители роли по порядку `HP/ATK/DEF/SPD`: guard `1.45/0.85/1.35/85`, striker `0.85/1.25/0.80/120`, caster `0.90/1.15/0.90/100`, construct `1.35/1.05/1.20/80`, beast `0.95/1.20/0.85/115`, wisp `0.80/1.10/0.80/110`.
- Тиры: normal `1.0/1.0`, elite `1.8/1.25`, miniboss `3.0/1.4`, boss `5.0/1.65` (HP/ATK). Для босса `DEF ×1.15`; в 5v5 босс занимает один слот, не весь состав.
- Автоатака каждые `clamp(2.0*100/SPD, 0.8, 3.5)` с. Энергия +100 за автоатаку, +35 за входящий удар; ульта 1000. Босс стартует с 250 энергии, обычный враг с 0. Урон, контроль, щиты и лечение имеют общие правила из документа героев.
- Контроль боссов ослаблен на 60%; запрет бесконечных цепочек контроля, накопление сопротивления при повторе в пределах 5 с. Босс не может призывать больше 4 помощников; всего на поле не более 5 противников.
- Телеграф ульты: 0.7–1.2 с визуальной подготовки; попадание рассчитывается сервером, VFX не влияет на результат. Фаза 2 при 50% HP **только** меняет поведение/эффекты, если сервер поддерживает триггер; иначе косметическая смена.

## 10. Формат данных и схема интеграции
Рекомендуемые новые файлы (не ломая существующий `campaign.json`): `content/packages/{version}/enemies.json`, `enemy_rigs.json`, `bosses.json`, `enemy_encounters.json`. Если существующий валидатор допускает только фиксированные документы, **сначала расширить схему/manifest/loader/Studio/валидацию**, затем подключать эти файлы. Не помещать динамический прогресс игрока в контент-пакет.
```json
{
  "schema_version": 1,
  "enemies": [
    {
      "id": "E01-01",
      "name_key": "enemy.E01-01.name",
      "rig_id": "RIG-GUARD",
      "skin_id": "skin_b",
      "role": "defender",
      "base_skill_ids": [
        "guard_attack",
        "guard_wall"
      ],
      "modifiers": [
        "normal"
      ],
      "asset_ref": "rigs/RIG-GUARD"
    }
  ],
  "bosses": [
    {
      "id": "B01-01",
      "name_key": "boss.B01-01.name",
      "rig_id": "RIG-GUARD",
      "stage_id": "CH01-10",
      "passive_id": "bureaucratic_barrier",
      "skill_id": "delay_order",
      "ultimate_id": "endless_queue",
      "phase_threshold_hp": 0.5,
      "portrait_ref": "portraits/portrait_b01_01.webp"
    }
  ],
  "encounters": [
    {
      "stage_id": "CH01-10",
      "slots": [
        {
          "enemy_id": "B01-01",
          "level": 10
        },
        {
          "enemy_id": "E01-01",
          "level": 10
        }
      ],
      "note": "Пример 2 из 5 слотов; остальные 3 брать из исходной кампании"
    }
  ]
}
```
- В production encounter **строго 5 слотов** или меньше, с `enemy_id`, `level`, `tier`, `variant_id`, `position`. Босс занимает один слот. Не хранить в JSON формулы как исполняемый код; использовать ID разрешённых механик.
- Ключи локализации `enemy.*`, `boss.*`, `ability.*`; русский первичный. В JSON стабильные ID, UI показывает локализованное имя.
- Для Godot: `EnemyCatalog`, `EnemyVisualFactory`/пул, `BattlePresentation`, `ContentPackageLoader`; использовать существующие узлы/сцены, не создавать дубли без аудита. Структуры боя серверные, локальный режим помечен DEMO.
- `manifest.json` обновляет SHA-256 каждого нового JSON; `active.json` обновляется только после валидации. HTTPS Live Content пока отдельная задача, не обещать обновление APK без нового клиента.
